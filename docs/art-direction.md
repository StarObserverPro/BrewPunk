# 插画与美术需求

玩家每次回来都能认出同一间厨房。台面高度、窗户方向、木架上的位置保持连续，锅里的颜色、发酵桶的泡沫线、桌上的增味物决定今天画面有何不同。第一次打开龙头时切到酒房，让厨房里的那桶酒在一个新地方再次出现。

## 火柴版和正式画稿

火柴版使用程序绘制的 SVG、剪影、线条和少量色块。移动端纵向排图和动作，桌面把厨房页与插画对排。正式稿沿用同一组状态和机位，把各层逐项替换为矢量或带透明通道的插画。下表是正式美术的交付清单，原型验收看动作和状态能否辨认。

| 机位 | 必须看得见 | 拆层交付 |
|---|---|---|
| 灶边备料 | 麦袋、称料的人、锅口 | 厨房底画、人物手势、麦袋、浅深麦粒 |
| 糖化与煮沸 | 俯看麦汁、过滤流出的液线、热端投花 | 锅口遮罩、酒液、蒸汽、漏斗与花粒 |
| 发酵角落 | 桶身、温度线索、实际发酵的痕迹 | 桶、液面、泡沫与桶壁残留、温度计 |
| 增味桌 | 投料前能认出物件 | 同一台面、手、砧板、每种原料的独立剪影 |
| 分装 | 一眼能分辨瓶、罐、生啤桶 | 灌装器、容器轮廓、容器内部液体与盖 |
| 自饮 | 杯沿透光处、正面深色、泡帽 | 同一尺度的杯身、液面、泡沫、照明 |
| 六头酒房 | 空头和在售头、桌上的几只杯、熟客 | 固定吧台、六个编号、酒牌、更换姿势的人物 |

液体颜色服从当前麦汁或成品的估算色度。色深、浑浊、泡层分别提供遮罩。一杯黑拉格和一杯浑浊 IPA 在去色时仍能靠透明度与轮廓分辨。增味层分别记录外观和风味参数。桌上画了樱桃，只表示玩家投过樱桃。酒客是否尝得到，交给本杯的感官模型。

## 画稿规格与验收

- 先做一个横构图母版，每个场景给出 4:3 和手机横幅的安全裁切范围。厨房核心动作、脸、锅口和龙头编号放进两种构图共有的区域。
- 物件按“底景、后排人物、器皿、酒液遮罩、手和前景物件”排层。每个可替换件记下场景、锚点、遮挡关系、层级及作者授权。交付原始可编辑稿与透明导出件。
- 熟客靠轮廓、坐姿、帽子和少量个人物件辨认。头像、语气与喜好各自变化；同一个懂酒的人也会只写半句话。
- 反馈首先来自画面与一行可读的线索。鼠标、触控、键盘都能完成动作。减少动态效果时，所有决定、线索和跳时仍可使用。
- 拿同一布局各画浅色清亮、深色轻酒体、浑浊浅色三杯，再给同一批酒更换三种包装。交给另一人辨认，任何只能读标签辨别的对象要回画。
- 当前仓库的火柴插图为项目原创。未来引入插画、字体或摄影时逐项保存来源和授权，正式稿进库前核对使用范围。
