# 插画与美术需求

当前本地主线已接入厨房与发酵角 16 张工序状态图。文件和来源保存在 assets/kitchen，接入与验证见 [轻小说界面集成说明](novel-ui-integration.md)。酒房和第一杯沿用下述程序插画，液色仍从模型取值。

玩家每次回来都能认出同一间厨房。台面高度、窗户方向、木架上的位置保持连续，锅里的颜色、发酵桶的泡沫线、桌上的增味物决定今天画面有何不同。第一次打开龙头时切到酒房，让厨房里的那桶酒在一个新地方再次出现。

## 火柴版和正式画稿

火柴版使用程序绘制的 SVG、剪影、线条和少量色块。移动端纵向排图和动作，桌面把厨房页与插画对排。正式稿沿用同一组状态和机位，把各层逐项替换为矢量或带透明通道的插画。下表是正式美术的交付清单，原型验收看动作和状态能否辨认。

| 机位 | 必须看得见 | 拆层交付 |
|---|---|---|
| 灶边备料 | 麦袋、称料的人、锅口 | 厨房底画、人物手势、麦袋、浅深麦粒 |
| 糖化与煮沸 | 俯看麦汁、过滤流出的液线、热端投花 | 锅口遮罩、酒液、蒸汽、漏斗与花粒 |
| 发酵角落 | 桶身、温度线索、实际发酵的痕迹 | 桶、液面、泡沫与桶壁残留、温度计 |
| 增味桌 | 能辨认投料动作和容器，袋口露出少量原料 | 台面、手、砧板、共用料袋、原料色块、器口遮挡 |
| 分装 | 一眼能分辨瓶、罐、生啤桶 | 灌装器、容器轮廓、容器内部液体与盖 |
| 自饮 | 杯沿透光处、正面深色、泡帽 | 同一尺度的杯身、液面、泡沫、照明 |
| 六头酒房 | 空头和在售头、桌上的几只杯、熟客 | 固定吧台、六个编号、酒牌、更换姿势的人物 |

液体颜色服从当前麦汁或成品的估算色度。色深、浑浊、泡层分别提供遮罩。一杯黑拉格和一杯浑浊 IPA 在去色时仍能靠透明度与轮廓分辨。增味层分别记录外观和风味参数。桌上画了樱桃，只表示玩家投过樱桃。酒客是否尝得到，交给本杯的感官模型。

## 画稿规格与验收

- 先做一个横构图母版，每个场景给出 4:3 和手机横幅的安全裁切范围。厨房核心动作、脸、锅口和龙头编号放进两种构图共有的区域。
- 物件按“底景、后排人物、器皿、酒液遮罩、手和前景物件”排层。每个可替换件记下场景、锚点、遮挡关系、层级及作者授权。交付原始可编辑稿与透明导出件。
- 熟客靠轮廓、坐姿、帽子和少量个人物件辨认。头像、语气与喜好各自变化；同一个懂酒的人也会只写半句话。
- 反馈首先来自画面与一行可读的线索。鼠标、触控、键盘都能完成动作。减少动态效果时，所有决定、线索和跳时仍可使用。
- 拿同一布局各画浅色清亮、深色轻酒体、浑浊浅色三杯，再给同一批酒更换三种包装。交给另一人辨认，任何只能读标签辨别的对象要回画。
- 当前仓库的火柴插图为项目原创。未来引入插画、字体或摄影时逐项保存来源和授权，正式稿进库前核对使用范围。


## 正式素材制作流程

画风采用数字油画、印象派方向。每张图保留一个明确的视觉中心，减少陪衬物件；先用短提示词表达主体和画风，遇到具体问题再补充。器型比例允许调整，以关键部件、接口位置和连接关系大致正确为验收依据。例如发酵桶应有桶身、桶盖、上部气锁和下部出液龙头，气锁接在桶盖上，龙头接在桶壁下部；重点是让玩家认出工具、理解操作。场景连续性、分层和液体状态仍按上文要求执行。

### 按素材用途选择路线

| 素材 | 默认流程 | 主要检查 |
|---|---|---|
| 普通场景、通用器皿与环境素材，如厨房、木桌、单杯啤酒 | 在已有浏览器标签中直接调用 Midjourney | 主体清楚、元素少、画风与光色合适 |
| 有一定重要性、又较为专用的酿造工具 | 搜索实物参考 → 预抠图与 photobash 粗拼 → imagegen 统一重绘 | 关键部件及连接关系可辨、拼接边缘融合、光线一致 |
| 已有结果中的局部问题 | 对具体部位做局部编辑；在 MJ 中使用 Select 选区后再描述修改 | 修补范围明确，已正确的结构尽量保留 |

文字生图把专用工具画成通用物品时，转入参考图路线。例如本次“玻璃发酵容器”被画成酒杯，继续堆叠文字的收益有限；实物图能直接给出气锁和龙头的结构。

### 普通素材：浏览器直接调用 MJ

以下是 2026-11-07 试验中跑通的最短操作范例。按钮名称以当时页面为准，执行时读取当前页面状态。

1. 先盘点浏览器和标签页，找到用户已打开、已登录的 MJ。多个 Edge 配置文件要一并检查；使用原标签，保留登录状态。本次 MJ 在 Personal 窗口，另一个 Work 窗口没有登录。
2. 进入 Create，检查输入栏是否有旧文字或附件。空栏直接输入；现有草稿需先确认能否清除。本次明确获准后使用 Clear prompt。
3. 输入短提示词，按 Enter 提交；等页面出现完成的四张候选，再看图挑选。沿用合适的页面设置，避免一次同时改变多项参数。本次为 V8.2、Standard、4:3、Stylize 100、Personalization Off。
4. 打开候选详情，让当前原图加载完成，再下载。此次稳定的自动化路径为：获取该标签的 `pageAssets` 能力 → `list()` → 按当前图片的原图 URL 精确选中资产 → `bundle()` → 把返回的本地文件复制到已选好的沙盒目录。逐张显示、逐张导出，随后验证图片能解码。直接请求 CDN 曾遇到访问校验；当前显示原图的页面资产导出已成功。
5. 同时保存实际提示词、页面参数、任务链接、原图和简洁对照图，方便后续复用。

厨房范例：

```text
Homebrewing kitchen, one copper kettle beside a sunlit window. Impressionist digital oil painting, broad brushstrokes, warm muted colors, simple composition. --ar 4:3
```

单杯啤酒范例：

```text
One glass of golden beer with a white foam cap, on a wooden table. Impressionist digital oil painting, broad brushstrokes, warm muted colors, simple composition. --ar 4:3
```

生成后看实际用途：场景中多出的器皿、影响裁切的构图、模糊的功能部件分别处理。短提示词已经得到合适结果时即可选用。

### 专用酿造工具：photobash → imagegen

1. **找能说明结构的实物参考。** 优先选择关键部件清晰、遮挡少、机位接近目标场景的图片；积极复用开放素材和已有背景。保存来源页面、图片地址、作者及授权信息。来源与授权待确认的参考留在试验记录中，正式稿采用前按上文要求核对。
2. **做适量预抠图。** 按轮廓粗抠主体，去掉明显的原背景边条，保住气锁、管路、龙头等细小部件。商标和说明文字可先清理。遮盖区域与周边材质、明暗尽量衔接，减少模型把遮盖块当成标签或新零件的机会。
3. **粗拼并处理边缘。** 把工具放到目标台面或场景里，位置、透视和比例达到可读即可。边缘按输出尺寸做轻微羽化，检查是否残留白边、黑边或背景色污染；小部件和接口处保留足够清晰的轮廓。补上接触阴影，让物件落在台面上。
4. **检查光线一致性。** 主体和底景采用同一主光方向；对齐色温、亮面位置、背光面的明暗及投影方向。预合成阶段先消除明显冲突，再让 imagegen 统一笔触与光色。
5. **用 imagegen 编辑粗拼图。** 将粗拼成图作为编辑目标，保留关键部件和连接关系，用简短指令要求统一画风。允许模型调整器型比例和局部外观。使用内置 imagegen 编辑即可；本次无需 API key 配置。
6. **看图验收，再做必要的局部修补。** 检查部件有没有缺失、多出或接错，检查边缘、阴影和画风是否统一。只有具体问题未解决时才追加编辑。保存参考、粗拼输入、重绘原图、实际提示词和对照图；确认可用后再按上文拆层交付。

本次 imagegen 与 MJ 首轮使用相同的粗拼图及以下同一句指令：

```text
Repaint as an impressionist digital oil painting, broad brushstrokes, warm muted colors. Keep the white bucket, clear airlock and bottom spigot.
```

在这一个样例中，imagegen 一次重绘就把白色遮盖块融进桶身，并统一了笔触和暖色；气锁和龙头仍可辨认，桶身比例有所变化。按本项目的验收要求，这类比例变化可以接受。结果中仍有深色边缘阴影，预抠图与轻微羽化可作为下一次输入准备的改进点。

### 局部修补经验：MJ Select

这次 MJ 整图重绘保留了粗拼中的遮盖块和黑边。后续整图指令去掉了遮盖块，用户指出选区工具后，改用局部编辑修补接缝：

1. 打开目标图片详情，点击 **Select**。
2. 使用 **Erase** 画笔涂选待重画区域。本次画笔值为 35，分别涂选桶身两侧黑边和桶盖暗斑；按当前显示尺寸调整画笔宽度，留出少量相邻材质供衔接，保护气锁和龙头。
3. 看清选区的棋盘格覆盖范围，输入修改描述并提交：

```text
Blend the bucket edges naturally into the painted background. Continue the white lid around the airlock. Soft oil-painted shading.
```

此次选区编辑补好了桶盖暗斑、收窄了部分黑边；未圈入的桶盖外缘仍有深色轮廓。后续修补按缺陷所在区域继续选取。

## 自定义增味的共用近景

投料时只露出袋口、落下的几粒和砧板上的一点碎屑。原料名称和用量由旁边的文字交代。新增的 `ui/adjunct-art.js` 提供完整的程序插画，任何名称都能用同一只料袋。玩家输入原料后，画面从画像读取深色、浅色或中性色三种之一；没有画像时使用中性色。颜色只表示投料时看起来的样子。

以左上角为原点，横向母版为 400 × 156。表中锚点以母版坐标标记。

| 从后往前的图层 | 本次近景 | 后续可替换的透明件 | 对位锚点 |
|---|---|---|---|
| 桌面与砧板 | 浅色底、木台、刀痕，砧板上留少量余料 | 一张厨房桌面局部和一张砧板；分层便于换台面 | 砧板前角 (194, 129) |
| 容器后半与液面 | 煮沸画蒸汽，接种画温度计，主发酵画泡沫，熟成画掀开的桶盖 | 锅或桶的后半、液面、四个状态各自的透明件 | 器口中心 (264, 85) |
| 衣袖与手掌 | 左侧袖子伸进来，手指扣住袋身 | 同一姿势的衣袖、手背；指尖单独留给前景 | 捏合处 (183, 34) |
| 料袋与原料 | 一个斜置纸袋，袋口留一道缝，三组色块共用外轮廓 | 纸袋、袋口内衬、单色原料遮罩；少数招牌配方可后补专用切片 | 出料口 (239, 68)，碎料落点 (246, 83) |
| 前景遮挡 | 袋口前折边、压在袋面上的指尖、遮住落点的容器前沿 | 三片独立透明件，保留原构图的前后穿插 | 锅前沿中心 (264, 93) |

手机优先把整张画等比缩进栏宽。必须裁切时，保留 x=122–308、y=23–134 这一块，先裁桌面两边和左侧袖口。在 320 像素栏宽下，袋口、碎料落点和桶沿之间仍应能读出“正在投料”。深浅色在同一尺寸并排验收，再切成灰度查看各阶段的蒸汽、温度计、泡沫和桶盖轮廓。将生僻原料名输入后应继续使用这幅近景；读屏标签说明原料色调与当前容器，具体名称和克数由表单提供。
