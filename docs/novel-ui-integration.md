# 轻小说界面与厨房工艺的本地集成

主线接入已评审沙盒的全屏场景、半透明读白与菜单、交叉淡入淡出、酒房透明滚动留言、手记与旧酒牌。ui/flow.js 管批次和酒席，ui/incidents.js 管场面与选择，core/process.js 将选择作用到工艺结果。页面刷新从当前选择或过场续接。

## 厨房素材

用户指定 workshop-expansion-r1 图库的 16 张工序图已复制到 assets/kitchen。来源与原清单见该目录的 SOURCES.md 和 source-manifest.json。每张图有正常流程或意外分支的入口，转罐采用带泵修订稿。数值覆盖层随裁切一同缩放，避免直接采用画稿里的示意温度。

## 接通的意外

| 节点 | 处置与实际影响 |
|---|---|
| 称量漂移 | 校零补料可缩小实投不足，重算比重与颜色 |
| 糖化走低 | 复测补温改善后半段的等效糖化温度，原先温差保留 |
| 过滤变慢、溢锅 | 排液或降火减少后续损失，供应体积采用实际收液量 |
| 投酵偏暖 | 等待冷却避免早期高温段，直接投酵则保留早期温度经历 |
| 第一晚升温 | 冰袋改善第二天桶温，第一晚实测保留 |
| 气锁进泡沫 | 换排气管减少后续泡沫损失，对应异常与恢复状态图 |
| 干投接触不足 | 检查浸润改善后续酒花提取 |
| 末段酸味 | 可改申报对照，杯中酸味仍按实际记录 |
| 木香提前明显 | 中途离木会缩短实际接触日数并改变风味 |
| 转移摄氧 | 检查接口减少后续摄氧，先前暴露保留 |
| 储存升温 | 恢复冷藏缩短偏暖时段，开喝与后续酒客感受按积分后的温度经历推演 |
| 首只容器异常 | 检查其余封口降低后续封口偏差，已取样容器保持原状态 |
| 酒头首杯泡沫 | 冷却酒线减少该晚首杯损耗；相应选择按酒席、夜次存档 |

新节点的概率、处置幅度与等效温度是游戏参数。糖化采用等效温度近似；过滤、溢锅与泡沫损失按体积比例记账，尚未建立逐段物料平衡。新开批次在配方中写 processVersion=2，既有配方缺省为 1，避免重算旧酒时额外插入新意外。所有随机流按批次和事件命名，刷新、重读与快进沿用同一结果。

安静的气锁可作为常规观察，继续由温度与发酵轨迹解释。多次复尝与主动撤回一段封罐容器仍需扩展状态；本轮先接上首只取样、封口检查与正常供应。

## 验证

30 项自动检查通过，覆盖原模型、扩展事件处置、六种新配方、供应量、存档恢复和留言进度。浏览器验证正常选方至上架、干投接触选择、溢锅的中断与续接、桌面及手机取景。离线打包将所有厨房图和运行模块内嵌到 dist/BrewPunk.html，构建约 60.4 MB；通过本地 HTTP 验证该文件实际渲染、图片为内嵌 data URL、仪表动态覆盖层以及无控制台错误。本轮未在 file:// 地址验证浏览器的本地文件存储策略。
