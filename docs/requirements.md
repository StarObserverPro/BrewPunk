# 火柴版的玩法与验收

## 一锅要能讲完

玩家写酒单、进厨房、看发酵桶、分装、尝第一杯，再把成品交给自家小酒房。目标是让人读完能想象味道，也记得这一锅经历过什么。每个底方都能走完整个流程，包括口味难以接受的批次。

| 场面 | 玩家能做什么 | 怎样验收 |
|---|---|---|
| 写酒单 | 用六种底方起步，选批量和酒名，替换主料并调整拼配 | 把部分基础麦芽等质量换成深色麦芽，色度随实际投入改变；总投料保持一致 |
| 灶台 | 选择糖化条件、早投苦花、旋沉或冷端干投 | 相同品种和克数移到不同阶段，IBU 和香气有不同响应 |
| 发酵桶 | 改菌株、温控、干投日；遇到异常后再作决定 | 慢发和快发走不同轨迹；补救时已发生的温度历史保留 |
| 增味与木桶 | 选择投料或原味，可快进至桶陈结束 | 投料、木材接触和后续储存分别影响成品；酒客未必猜出配料 |
| 分装 | 选生啤桶、瓶或罐，定温度、开喝日 | 同一包装的一组分享者体验相关，封装故障有具体归属 |
| 第一杯 | 按跨风格标尺读中性风味，另选申报类别看模拟评分 | 换申报风格只改变评审。改变取样条件可以改变杯中风味 |
| 六席酒房 | 展示在售批次，按进度看动态，同时开下一锅 | 空位可见、可选；不同批次留言不会串在一起；刷新后回到同一进度 |
| 晚间动态 | 看短评、长评、偶尔的回帖、分尝和续杯 | 留言里至少有一个对酒的反应，客人可以读错酒牌或猜错原料。原料真相不进入文字模型上下文 |

自定义增味需覆盖同物异剂量、后投不改历史酒精度、未知材料保守结算和无图复用。参见[增味裁决](adjunct-adjudication.md)。

## 节奏

以 25 L 为默认，一锅通常在 20–40 L，大锅可达 50 L。一美制品脱约 473 mL，25 L 理论上约 53 个整品脱，实际还有分尝、小杯、酒损。杯数、人数和留言数分别记账。默认客流要让玩家在本次游玩就能读到动态；无须为打卡而经营一套排班、进货、销售系统。

开桶日属于玩家的配方目标。鲜饮 IPA 可以比较一周和一个月，一款以三个月为目标的酒也能在那天开。木桶接触最长两年。玩家可以跳时；状态的计算依旧依照工艺时间或包装后的实际日龄。

## 可复算的例子

选 25 L 美式淡色艾尔，酿造种子取 1。底方约为 6.1 SRM、31.0 IBU。在同一随机条件下额外把 40 g Citra 煮沸 60 分钟，估算值约 75.2 IBU；将同量酒花改在第 5 天干投三天，则约 31.0 IBU，酒花香从 6.5 升到 7.5。改为等质量置换占总投料 10% 的黑麦芽，色度约 37.5 SRM。这里的数值记录游戏的响应，改动模型时可以复算，不作为实酿浓度或品饮测试结果。

25 L 浑浊 IPA 取酿造种子 24，再以品鉴种子 17 重复模拟 100 场，得到评论数的 P10/P50/P90 为 27/34/40。25 L 与 50 L 的读评篇幅相近靠发帖概率调节，酒量始终按毫升扣除。

## 文字与画面

每一步使用已注册的厨房／酒房插画或火柴备图、当下这一项决定、必要反馈。客观酒评回答“杯里是什么”，BJCP 评审回答“和申报风格差在哪里”，酒客动态让人知道“谁在什么情境下喝到”。客人能夸能骂，有自己的口味和当天的事。原帖可以只写半句，回复可以只接朋友的闲话。

| 本版验收物 | 后续可替换的位置 |
|---|---|
| 工序插画、固定机位、透明叠层及 SVG 备图 | 可替换的砧板遮罩、暗色料包与手部遮挡层，详见[美术要求](art-direction.md) |
| 固定种子的机理近似与游戏先验 | 用实际酿造记录校准酒花批次差、偏差分布和香气衰退速度 |
| 本地中文打卡与服务端 Luna 客人视角改写 | 扩充常客声音与长期回忆 |
| 同一制造批次选一种主要包装 | 将同锅拆成多个分装批号，带去聚会的瓶罐可在数周后单独回评 |
